# svc

Python CLI for homeserver Restic backups and restores.

## Development (uv + nvim)

```bash
cd hosts/homeserver/backup/svc
uv sync
source .venv/bin/activate
svc --help
```

View all retained logs for the scheduled local or remote backup:

```bash
svc logs local
svc logs remote
```

Run Restic directly against either configured repository. Arguments after the
repository selector are passed through to Restic:

```bash
sudo svc restic remote snapshots
sudo svc restic remote unlock
sudo svc restic local check --read-data-subset=1/12
```

Arguments after the repository selector belong to Restic, including options
such as `-v`, `--dry-run`, and Restic's own `--` separator:

```bash
sudo svc restic remote snapshots -v
sudo svc restic local backup -- -leading-dash
```

Place `svc` global options before the subcommand. For example,
`sudo svc --dry-run restic remote unlock` prints the command without executing
it.

Typer provides shell completion through `svc --show-completion` and
`svc --install-completion`. The homeserver loads the generated Zsh completion
script automatically.

## Notes

- Runtime config defaults to `/etc/svc/services.json` (generated by Nix on the homeserver).
- Restic credentials are read from `${secretsRoot}/restic/<local|remote>.env` (defaults to `config.homeserver.paths.secretsRoot`).
- `svc restore <local|remote> k3s latest` is destructive: it stages the backed-up
  k3s server token and newest etcd snapshot, stops k3s, runs the current
  `k3s.service` command with `--cluster-reset`, installs the backed-up server
  token, and starts k3s again.
